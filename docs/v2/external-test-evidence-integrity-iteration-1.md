# V2 外测证据完整性迭代 1

日期：2026-07-17

本轮结论：**`V2-030 / P1` 已在仓库内关闭。外测分析入口不再把“轮次和四个布尔值齐全”视为可判定证据；每轮必须使用单一冻结构建，R2 必须是新提交，匿名编号必须与轮次一致，且有效样本必须满足经验/设备分层、观察时序和访谈原始回答完整性。真实模板仍为空，四个外测质量门槛继续为 `pending_external`。**

## 1. 原有风险

旧分析器可以识别重复 ID、技术失败和四项阈值，但以下内容没有进入机器契约：

- 同一轮是否混入多个构建；
- R2 是否真的使用诊断轮修复后的新提交；
- `R1` 行是否误填成 `R2-Pxx`；
- 每轮是否至少包含 2 名轻度玩家、2 名中重度玩家；
- 是否同时覆盖小屏 iPhone 和常规/大屏 iPhone；
- 四个结果布尔值背后是否有实际访谈回答与关键时间点；
- 技术失败行是否一边被排除、一边又填写了产品指标。

因此，只要写 10 行结构合法的 `true`，就可能得到外测 PASS。它不能证明数据是伪造的，但也不足以拒绝明显不符合协议的证据包。

## 2. 记录契约

模板新增两个判定字段：

| 字段 | 允许值 | 用途 |
| --- | --- | --- |
| `experience_segment` | `light` / `mid_heavy` | 每轮至少各 2 名有效参与者 |
| `device_segment` | `small_iphone` / `regular_large_iphone` / `ipad` | 每轮至少 1 场小屏 iPhone、1 场常规/大屏 iPhone |

其余字段现在也进入严格校验：

- `participant_id` 必须采用 `R1-P01` / `R2-P01` 形式，并与行内轮次一致；
- `test_date` 使用 `YYYY-MM-DD`，`t0_start` 使用 `HH:MM` 或 `HH:MM:SS`；
- `build_commit` 是仓库内可解析到 commit 对象的 7～40 位 Git SHA；同一轮所有行必须相同，R1/R2 不得相同，且 R2 必须是 R1 的后继提交；
- 设备、系统版本、主持人匿名代号和既往品类经验不可为空；
- `T1`～`T7` 若填写，必须是非负整数且按发生顺序单调不减；
- 声称独立进入首次远航必须有 `T2`，声称理解双阶段战斗必须实际到达 `T4`；
- 有效场次必须保留 8 项结束访谈原始摘要，不能只写最终布尔值；
- 技术失败场次的四项产品指标必须留空，并填写外部阻断原因。

自由文本只检查存在性，不自动判断玩家回答是否“正确”。四项布尔判定仍由观察者按协议编码，原始回答用于复核与争议追溯。

## 3. 样本完整性与指标判定

每轮只有同时满足以下条件才计为 `sample_complete`：

1. 至少 5 名非技术失败的有效参与者；
2. 至少 2 名 `light` 与 2 名 `mid_heavy`；
3. 至少 1 场 `small_iphone` 与 1 场 `regular_large_iphone`；
4. 全轮使用同一 `build_commit`，且 R2 使用不同于 R1 的新提交；
5. 所有有效行通过来源、时间与访谈证据校验。

只有样本完整且 R2 四项比例逐项达到门槛时，输出才是 `external_decision: PASS`。这仍然只代表外测指标，不代表总体 GO；真机、P0/P1、内部质量、预算和最终发行门禁继续独立判定。

## 4. 报告变化

聚合报告的 Sample 表新增：

- 每轮冻结提交；
- 有效/技术失败数量；
- 轻度与中重度样本数；
- 小屏与常规/大屏 iPhone 场次数。

若数量不足，blocker 会指出具体轮次和缺少的样本类型，不再只报告总人数。

## 5. 自动回归

`test_analyze_user_tests.py` 现在覆盖：

- 两轮合格样本与四项通过；
- R2 指标低于阈值；
- 技术失败正确排除、有效样本不足；
- 非法布尔值；
- 轮次内混用构建、R1/R2 复用同一构建；
- 填写为 SHA 形式但仓库中不存在的构建提交；
- R2 指向旧提交或不继承 R1 冻结构建的分叉提交；
- 参与者 ID 与轮次不一致；
- 访谈证据缺失；
- 技术失败行仍填写产品指标；
- 时间点倒退；
- 经验分层不足时保持 HOLD。

`validate_phase4.py` 同时锁定新字段和完整性规则，空模板检查继续存在，防止仓库用合成参与者结果关闭外部门槛。

## 6. 后续真实执行

1. 从空模板复制实际记录文件，不直接修改仓库模板；
2. 第一轮冻结一个已提交构建并完成至少 5 名有效参与者；
3. 登记、修复并提交诊断轮 P0/P1；
4. 第二轮冻结新的提交，使用未参加 R1 的新参与者；
5. 运行分析器并保存原始匿名 CSV、聚合报告和问题复验记录；
6. 即使外测 PASS，也要等真机与其余总体门槛完成后再更新最终决策。

本轮没有创建任何实际参与者行、没有推断访谈回答，也没有把 `quality_gate.csv` 的外测状态改成通过。
