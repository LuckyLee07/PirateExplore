# V2 第一章内部样片冻结审计

审计日期：2026-07-17

当前结论：

- **内部样片：FROZEN（冻结，可作为后续外测候选基线）**
- **产品立项：HOLD（未获准扩建前三海域）**
- **发行上线：HOLD（真机、外测、账号与 App Store 外部证据未完成）**

这三个结论必须同时使用。“内部样片冻结”只表示当前首章的内部开发目标已经闭环，继续增加功能的边际价值低于把样片交给真实设备和目标用户验证；它不代表正式产品完成，也不代表允许开始第二海域。

## 1. 审计依据与范围

产品定位、原始策划与美术资产的详细还原仍以 [`../product-iteration-plan-v2.md`](../product-iteration-plan-v2.md) 为权威基线。该基线建立在当前 `NewPirate` 工程，以及 Desktop `Pirate/策划`、`Pirate/美术` 和 `Pirate/Develop` 历史工程的完整审阅之上。

本次冻结审计不重新发明方向，只核对以下问题：

1. 15～20 分钟首章纵切是否形成完整、可恢复的玩家闭环；
2. 六轮内部精修是否覆盖最关键的理解与信任缺口；
3. 工程、数据、资源、存档和发行级回归是否可重复；
4. 尚未完成的事项是否都属于必须由真实设备、外部用户或账号负责人提供的证据；
5. 当前是否还有理由继续内部堆功能。

审计不把开发者判断、模拟器操作、自动脚本或空白模板冒充外部用户结论。

| 舰炮战 | 攻击甲板或火炮，船员技能参与 | 接舷前预估甲板破坏会把敌军从 100/100 降到 65/100 |

## 5. 冻结判定

### 5.1 为什么现在应冻结

首章的开场、准备、探索、战斗、奖励、成长、失败和完成已经形成可回归闭环。最近四轮分别修正了玩家最容易误解的四条因果链，继续内部添加内容或系统不会回答“目标用户是否独立理解、愿不愿意再出航”这两个关键产品问题。

因此内部开发结论为 **FROZEN**：保留当前功能、数值、数据 schema、四个英雄画面和首章范围，等待外部证据。

### 5.2 冻结期间允许的改动

- 修复新发现的崩溃、死路、存档损坏、数据引用错误和发行构建失败；
- 修复明确复现的 P0/P1，不改变核心循环范围；
- 完善外测记录、真机记录、签名和 App Store 证据工具；
- 对候选提交做可重复构建与证据归档。

### 5.3 冻结期间禁止的改动

- **不得扩建第二海域**、第三海域或十六海域内容；
- 不新增长期生产树、商城、抽卡、广告、排行榜、竞技场或七日系统；
- 不为“看起来更完整”重写引擎、战斗框架或港口空间；
- 不在没有玩家证据时继续反复改文案和数值；
- 不把 Development 签名、模拟器截图或内部人员试玩记为 TestFlight/外测通过。

## 6. 后续迭代方向与顺序

以下工作属于冻结后的外部验证阶段，本审计只定义顺序，不要求现在立即执行真实设备或发布操作：

1. 以冻结提交生成唯一候选 ID，锁定 Git SHA、Release archive 和测试说明；
2. 条件具备时，在低端 iPhone、现代 iPhone、iPad 上完成同候选真机矩阵；
3. 执行第一轮至少 5 名目标用户测试，记录过程时序和访谈原始摘要；
4. 只修第一轮产生的 P0/P1，生成新的冻结候选；
5. 用至少 5 名新参与者执行第二轮，按四项阈值复判；
6. 只有第二轮、真机、问题清零和内容预算同时通过，才把阶段 4 从 HOLD 改为 GO，并限额批准第二/第三海域；
7. 产品 GO 后再补齐分发账号、公开页面、App Store Connect 和 TestFlight/上传候选一致性。

若外测门槛未通过，重新打开首章纵切进行 2～4 周定向修正；修正必须对应真实观察到的问题，不恢复无边界的内部功能迭代。
