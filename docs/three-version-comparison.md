本说明只描述代码、运行和验证边界。三份分支存在不等于三份可安装体验包已准备好。当前实现的原生入口是 Linux x86-64；Mac、Windows、iPhone 的目标设备与打包方案须另行确认。本分支缺少完整 Apple、Windows、Android 游戏工程，不能把其他开发线的设备结果套用到这里。

## 2. 四层隔离

每一版、每一轮使用单独的：

1. 源码目录：完整 SHA 的只读/静止快照；不指向仍在开发的工作树。
2. 构建目录：构建缓存、可执行文件及引擎资源不跨版本混用。
3. 配置与存档目录：独立 `HOME`、`XDG_CONFIG_HOME`、`XDG_DATA_HOME`、`XDG_CACHE_HOME`。Linux 引擎实际写入 `$XDG_CONFIG_HOME/PirateExplore/`，包含游戏数据和 UserDefault。
4. 证据目录：完整 SHA、tree、二进制 SHA-256、资源链接解析结果、启动参数、时间、日志与人工观察。

例如，准备目录可以是 `comparison/A-source`、`comparison/B-source`、`comparison/C-source`，构建输出在各自 `build/linux`，每轮数据在另一个新的 `comparison-runs/<版本>-<轮次>`。上述名字只是布局约定，不表示目录或包已生成。

构建系统在可执行文件旁创建 `Resources` 和 `engine-scripts` 符号链接。必须使用 `readlink -f` 确认它们分别指向**该版本**的 `bin/res` 和引擎脚本目录。二进制哈希相同不能证明运行资源相同。历史 `initial.sh` 所指目录已经装载 UI 资源，不是合格的 A 启动器。

## 3. Linux 准备与运行

### 准备前提

需要 Linux x86-64、CMake 3.18+、C/C++ 工具链、GLFW、FreeType、WebP、仓库引擎依赖、可用图形显示和中文字体。历史云端的独立依赖目录不是用户电脑已安装依赖的保证。不能将 ELF 当成 Mac/Windows/iPhone 安装包。

以下是仓库真实接口，须在已经核验并隔离好的各版目录中执行。A 仅适用于已批准且恢复完成的历史 Linux 兼容快照，不适用于裸 `c53323e`。

```bash
# 当前目录必须是预先准备的独立版本目录。
git rev-parse HEAD
git rev-parse HEAD^{tree}
git status --porcelain
./linux.sh build
readlink -f build/linux/bin/Resources
readlink -f build/linux/bin/engine-scripts
sha256sum build/linux/bin/PirateExplore
```

不得忽略未提交的游戏脚本改动。新构建完成后仍须核实链接路径；旧构建目录可能保留指向另一工作树的资源链接。版本窗口标题也不足以证明实际源码身份。

使用每次新建的目录运行（在可用图形环境下）：

```bash
RUN_ROOT=$(mktemp -d /tmp/pirate-comparison-XXXXXXXX)
mkdir -p "$RUN_ROOT/home" "$RUN_ROOT/config/PirateExplore" \
  "$RUN_ROOT/data" "$RUN_ROOT/cache"
# 如显示服务依赖 ~/.Xauthority，先保留实际 XAUTHORITY 的绝对路径。
export HOME="$RUN_ROOT/home"
export XDG_DATA_HOME="$RUN_ROOT/data"
export XDG_CACHE_HOME="$RUN_ROOT/cache"
PIRATE_SAVE_DIR="$RUN_ROOT/config" ./linux.sh run 480 800 \
  >"$RUN_ROOT/runtime.log" 2>&1
```

`PIRATE_SAVE_DIR` 是当前 `linux.sh` 的实际入口，它覆盖 `XDG_CONFIG_HOME`。只设 XDG 变量而保留另一个 PIRATE_SAVE_DIR，可能会启动错误的存档。保留显示和音频所需的原环境变量；不要复制玩家配置来解决显示授权问题。

该运行命令不是三版均已验收的声明。A 兼容运行恢复、B 隔离启动以及 C 最终提交的原生验证，需各自记录完成证据。仅 Lua 单测、无窗口启动或浏览器原型，均不等于原生完整试玩通过。

### 防混版启动器

新增 `tools/comparison/launch-linux-isolated.py`（Python 3.11+）。只读预检示例：

```bash
python3 tools/comparison/launch-linux-isolated.py \
  --label B-ui-frozen \
  --source /absolute/path/to/verified-B-source \
  --commit FULL_LOCAL_COMMIT_SHA \
  --binary /absolute/path/to/verified-B-source/build/linux/bin/PirateExplore \
  --binary-sha256 SHA256_FROM_MATCHING_BUILD_RECORD \
  --save-root /absolute/path/to/comparison-runs/B-round-01 \
  --check
```

大写字段和路径是必填占位符，不是现成体验包。核验通过后移除 `--check` 才会启动；父目录须已存在，save-root 本身必须不存在。`--check` 不创建目录、不启动游戏。启动前会输出标签和完整 SHA，随后写 manifest.json 与 runtime.log；没有自动 checkout、patch、删档或 resume。脚本保留显示/依赖环境，隔离本轮 HOME、配置、数据和缓存。

启动器检查 clean HEAD、完整本地 SHA、ELF x86-64 标识、指定二进制 SHA-256、Resources/engine-scripts 的精确链接及源码中的存档接口。`PIRATE_SAVE_DIR` 由 linux.sh 转成 `XDG_CONFIG_HOME`，不是 ELF 直接读取的变量；启动器直接启动 ELF，并把两者设为同一个新路径。它检查被跟踪的 wrapper/引擎接口及二进制中的 XDG_CONFIG_HOME 标识，但这些预检不能独立证明二进制确实由该源码构建，更不能代替原生运行验证。指定哈希应取自对应构建验收记录，不能随手对未知二进制算一个哈希后当成来源证明。

若公共 SHA 与本地 SHA 不同，先完成上一节的来源/tree 映射核验，再将明确的本地完整 SHA 传入；脚本不会猜测映射。原版兼容对象未恢复、源码仍 dirty、资源链接混版、旧存档目录已存在或哈希不符时均拒绝启动。准备后须保持快照不变；脚本不是文件系统沙箱，也不能防止其他进程在启动后改动源码。

验证范围：10 项文件系统预检回归通过（正常无写入检查、HEAD 不符、分支名替代 pin、dirty tree、两类资源串版、旧档保护、哈希不符、缺存档接口、存档位于源码内）。该回归使用测试夹具，不执行游戏。另外，对当前正在开发的 dirty checkout 实测预检正确拒绝，未创建存档。尚未借此启动器执行三版原生 GUI；原生验收须单独记录。

```bash
PYTHONDONTWRITEBYTECODE=1 python3 tools/comparison/test-launch-linux-isolated.py
```

## 4. 新档与旧档检查

- 三版正式对照均从独立新档开始。不得共享 gameRole、队列、材料、UserDefault 或进度；不得从测试夹具补钱、补材料、跳教程后称为自然流程。
- 保留用户旧档不动。兼容检查只能复制到**另一个单独新建的兼容检查目录**，记录复制前后哈希，且不覆盖原件。确认旧档来源版本；未确认的不参与结论。
- “旧档可加载”与“从新档体验”是两项检查；兼容检查存档不能再用于自然流程对照。新版读取后可能写入迁移字段，禁止把其覆盖回旧版。
- 旧档测试只允许显式启动复制品；新档启动器不应提供隐式复用/清空旧档行为。
- 若中断后继续同一轮，需要保留该轮 manifest 并显式核验版本一致。新的一轮必须另建目录，不能偷偷删档重置。
