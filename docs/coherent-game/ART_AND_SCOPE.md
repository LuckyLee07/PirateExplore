# Visual system and art scope

This pass uses the already shipped clean voyage sea, harbor and northeast boat in Home, preparation and ship previews. Their original provenance remains in `docs/clean-first-voyage/` and `docs/art-sources/`; no new AI art was generated in this pass. The inherited two painted boat occupants remain scenery, not an additional owned crew grant. The actual crew action shows saved owned/selected counts.

The shared native UI uses CleanVoyageSans, navy ink, cream readable content surfaces, teal primary actions and restrained separators. Harbor is the open scene; preparation and results use an intentional navy title band over the same cream content system. Modal scrims are navy. Status symbols use native vector geometry; hammer/chest/bag/map/log use the existing Warm functional prop atlas. Food uses the real original bread icon, not a neutral document placeholder.

Opening-story artwork and combat actors/decks remain inherited content. Opening illustrations are framed as narrative vignettes with the shared typography and readable native Next control. This is not a claim that all story/combat/crew/resource art has been redrawn into low-poly models. Later maps and old profiles retain original geography and map rendering. Their shared screen-space chrome is updated; only versioned new-profile map 1 uses the clean world adapter.

## Intentionally preserved rules

- Production economy, event choices, combat timing/damage, food, crew loss and capacity.
- Departure/return/upgrade save and transaction owners.
- Original free/scroll/diamond return terms and original mission-item failure exceptions.
- No new real-money charge, online-service simulation, free sailing or save migration.
- Existing original business/utility route availability, including supported offline unavailable-service responses.

## Remaining visual depth

Shared framing does not mean every original business page was compositionally redesigned. The focused forge route is simplified because it lies on the first growth loop; unfocused production/training/store/talent/achievement pages preserve their existing workflows, with shared visual framing. Individual page composition, additional illustrated icon families and later chapter environments remain follow-on work, requiring their own actual native acceptance. No all-screen fidelity or Mac/mobile claim is made.
